# 输入路由与工作节奏

## 先识别输入成熟度

| `inputMode` | 用户已有内容 | Skill 的首要任务 |
| --- | --- | --- |
| `idea` | 一个观点、问题或创作想法 | 展开 2–6 个方向，区分创意假设与待核验事实 |
| `article` | 完整文章或公众号内容 | 提取可独立成立的判断，不等比例压缩全文 |
| `outline` | 结构和要点 | 检查逻辑闭环、证据缺口与节奏 |
| `script` | 已有口播 | 审核事实、口语性、时长和视觉潜力，不擅自重写已确认表达 |
| `source-pack` | 多份资料、界面、数据或案例 | 建立来源账本，形成带锚点的内容候选 |
| `audio` | 已录音或现成声音 | 先转写并确认是保留原话、整理口播还是只做字幕/画面 |

## 统一成 VideoBrief

无论入口是什么，都记录：

- `id` 与 `inputMode`；
- 用户原始想法摘要；
- 来源文件、当前状态、权利和证据成熟度；
- 受众与期望变化；
- 平台、时长、画幅和品牌限制；
- `voiceIntent.mode`：`none`、`human`、`synthetic` 或 `cloned`。

不要让输入路径直接决定最终视频。例如文章不必做成一条完整视频，一个想法也不等于可以跳过事实核验。

## 想法输入的协作方式

先复述用户真正要表达的矛盾或判断，再给出候选。允许补充结构、比喻和表达路径；涉及现实数据、产品能力、法律结论或他人案例时，写入 `verificationNeeds`，未核验前不得进入最终事实审核。

## 声音节奏决策

1. 用户不需要克隆声音：不执行 VoiceProfile 建档。
2. 用户首次需要克隆声音：完成授权和校准链，形成可复用 Profile，再开始完整视频生产。
3. 已有 Profile：项目启动时 preflight；口播确认后才创建本次 VoiceRun。
4. Profile 漂移：停止本次配音，恢复到校准或重新授权，不影响已经完成的内容对象。

“先做声音”只适用于建立可复用能力；“本次正式配音”必须位于口播人工确认之后。
